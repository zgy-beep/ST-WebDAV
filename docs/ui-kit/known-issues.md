> 记录向上游 `zgy-beep/ui-kit` 提交的 issue 及其在本项目的落地状态。
> 规范见 [`issue-reporting.md`](issue-reporting.md)。

**状态取值：**

| 状态 | 含义 |
|---|---|
| `待上游确认` | 已提交，等上游判断是否成立 |
| `已确认-待修复` | 上游已确认，等待修复 |
| `已修复待同步` | 上游已修复，等升级内置副本 |
| `已同步` | 已升级内置副本并移除临时隔离层 |
| `已确认-不修` | 实测证明非问题或设计上如此（**必须附实测数据**） |

## 使用说明

**新增一行时：**

1. 确认已按 `issue-reporting.md` §4 提交上游 issue。
2. 填入**上游 issue 编号**并链接。
3. 「本项目应对」列写清楚：是否有临时隔离层、文件在哪。

**状态流转：**

```
待上游确认 ──▶ 已确认-待修复 ──▶ 已修复待同步 ──▶ 已同步
      │              │
      │              └──▶ 已确认-不修（须附实测数据与复现脚本）
      └──▶ 已确认-不修（须附实测数据与复现脚本）
```

**「已同步」的完成条件：**

- [ ] 内置的 `src/client/vendor/ui-kit/` 副本已升级到修复版本
- [ ] 跑通 ui-kit 自身测试与本项目全量测试
- [ ] 对应的临时隔离层已删除
- [ ] 本项目 CHANGELOG 已记录此次升级
