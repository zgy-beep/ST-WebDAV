# 发版实机验收清单（Manual QA）

> **状态：待执行模板**（建立于 2026-10-26）。
> 本文件只定义验收项、操作步骤与预期结果，**不记录也不代表任何版本已通过验收**。
> 每次发版的真实结果填入各节「执行记录」表，并随 release PR / release issue 留档。

- 适用对象：ST-WebDAV 发版前的实机验收，即自动化测试覆盖不到的部分。
- 关联流程：[`versioning.md`](versioning.md) §8 第 ④ 步「全量验证」。
- 自动化边界：`tests/` 全部为 `node:test`，WebDAV 交互使用内存或临时 HTTP mock，
  **不覆盖**真实网盘、浏览器 UI、宿主主题与移动端布局 —— 这些必须人工执行本清单。

## 1. 使用方式与记录约定

### 1.1 执行时机

| 触发场景 | 必须执行的章节 |
|---|---|
| 发版前（候选版本冻结后、打 tag 前） | 全量执行第 3～8 节 |
| 升级内置 ui-kit | §4、§5；必要时回归 §3 |
| 改动前端面板 / 宿主交互 | §4、§5，并回归 §7 |
| 改动加密 / 还原 / 共享 / 轮转 / 定时任务 | 对应章节 + §3 至少 1 家真实服务端 |
| 升级 SillyTavern 宿主 | §4、§5 + §3 至少 1 家真实服务端 |

### 1.2 记录列（所有执行记录表通用）

| 列 | 填写要求 |
|---|---|
| 日期 | `YYYY-MM-DD` |
| 插件版本 | `package.json` 中的 `version`（如 `1.2.3`） |
| ui-kit 版本 | 面板「服务设置 → UI Kit 模式与扩展源」显示的实际版本 |
| 宿主 / 浏览器 | SillyTavern 版本 + 浏览器及版本；移动端写设备型号与系统版本 |
| 执行人 | 真实姓名或团队 ID |
| 结果 | `PASS` / `FAIL` / `BLOCKED`，不得留空 |
| 备注 | 失败写现象、报错文案、控制台日志；BLOCKED 写缺失的环境 |

### 1.3 结果判定

- **PASS**：该节全部预期均满足，且浏览器控制台与 SillyTavern 日志无新增报错。
- **FAIL**：任一预期不满足。记录证据 → 开 issue → 修复后从该节首项全量回归。
- **BLOCKED**：缺少服务端 / 账号 / 设备等环境。发版前必须补齐，或由负责人书面接受风险。
- **未执行**：一律视为「未验收」，不得按通过处理。

## 2. 环境准备

| 项 | 要求 |
|---|---|
| 宿主 | SillyTavern 已配置 `enableServerPlugins: true`，插件按 README 部署（软链接或克隆） |
| 运行时 | Node.js 22；依赖安装成功；`npm test` 全绿（自动化前置，不替代本清单） |
| 浏览器 | 桌面 Chrome / Edge 最新稳定版至少各 1 个；移动端真机或 DevTools 设备模拟 |
| 单用户环境 | 默认账号可打开面板并完成一次备份 |
| 多用户环境 | 至少 2 个账号 A、B（其中一个可非管理员），均可访问同一 WebDAV 根目录 |
| WebDAV 账号 | 6 家服务端各 1 个测试账号（见 §3.2），使用**专用测试目录**，不碰生产数据 |
| 加密测试 | 一个正确口令 + 一个错误口令；一份由旧版本（v01 格式）生成的加密备份夹具 |
| 玻璃回退 | 可禁用 `backdrop-filter` 的浏览器（如 Firefox 关闭该项首选项） |

> 测试账号、应用密码、加密口令**不得写入仓库**；验收结束后清理远端 `_shared/` 与测试目录。

## 3. WebDAV 服务端兼容（6 家）

### 3.1 通用步骤（每家服务端各执行一遍）

前置：已在对应服务端创建测试目录，凭据可登录；在面板「服务设置」填入 URL、用户名、密码。

| 编号 | 操作步骤 | 预期结果 |
|---|---|---|
| DAV-01 | 点击「测试连接」 | 提示「连接成功！……」；失败时给出可读错误，无未捕获异常 |
| DAV-02 | 备份操作 → 核心配置 → 立即备份 | 进度条推进到 100%；成功提示；远端出现 `ST_Backup_*_core_*.zip` |
| DAV-03 | 远端历史 → 我的备份 → 刷新列表 | 出现该备份卡片，显示时间、大小、「核心」徽章与备注 |
| DAV-04 | 对 DAV-02 的备份点「还原此备份」 | 二次确认后下载（GET）并还原成功；配置与备份内容一致 |
| DAV-05 | 删除 DAV-02 的备份并确认 | 卡片消失，远端文件被删除；刷新后列表数量减一 |
| DAV-06 | 检查控制台与 SillyTavern 日志 | 无未捕获异常；无凭据明文出现在日志、URL 或前端存储 |

> 每家服务端 DAV-01～06 应全部 PASS。若某服务端不支持 `COPY`，§7 分享项记 BLOCKED 并注明。

## 9. 发版时如何使用本清单

1. **候选版本冻结后**：复制本文件到 release PR / release issue，或直接在仓库副本中填写。
2. **先跑自动化**：`npm test` 全绿；本清单不替代自动化测试，只补人工覆盖。
3. **准备环境**：按 §2 配齐宿主、浏览器、6 家 WebDAV 账号、多用户账号与 v01 夹具。
4. **逐节执行**：按 §3 → §4 → §5 → §6 → §7 → §8 顺序执行，边执行边填记录；失败即记证据。
5. **判定**：全部 PASS，或 BLOCKED 项已由负责人书面接受，才可进入 `versioning.md` §8
   的打标签步骤；任一 FAIL 不得发版。
6. **归档**：把填写后的记录附在 release notes / issue 中，正文清单保持为空模板。
7. **下次回归**：按 §1.1 的触发条件选择重跑章节；ui-kit 版本变化时必须重跑 §4、§5。

> 清单应随线上问题增长：每修一个「自动化没抓到、人工才发现」的缺陷，
> 就在对应章节补一项检查，并标注引入该检查的版本。
