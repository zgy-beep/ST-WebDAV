# ADR-002：共享区采用「分享者本人或管理员」权限模型

- 状态：已接受
- 日期：2026-10-26
- 相关：无上游 issue；依据 CODE_REVIEW.md 的 M2/M3/M4/M5 与 index.js 共享区路由

## 背景

跨账号共享区固定为 `<基础目录>/_shared`，不带用户 handle 前缀，所有能访问该
WebDAV 路径的用户与账号共用同一片空间，且不受用户目录隔离开关影响
（`src/server/UserHelper.js:99-111`、`src/server/SharedService.js:8-13`）。

共享区早期有两类安全缺陷：

- 任意用户可删除他人的共享文件：撤回时**没有索引记录**就跳过权限校验
  （`CODE_REVIEW.md:102`，M3）；
- 用户目录混放模式下 `/delete` 可删任意文件，后来按文件归属前缀收紧
  （`CODE_REVIEW.md:101`，M2；`index.js:388-396`）。

此外共享区元数据是单个 JSON 索引，读写存在并发丢更新风险（`CODE_REVIEW.md:103`，
M4）；分享时源文件必须确实在调用者自己的远端目录（`CODE_REVIEW.md:104`，M5）。

## 决策

1. 共享区位置固定：`resolveSharedDirectory()` 始终返回 `<base>/_shared`
   （`src/server/UserHelper.js:108-111`）。
2. 分享：只允许分享调用者当前生效的远端目录中真实存在的备份文件
   （`SharedService.js:143-148`）。
3. 同名冲突：若同名备份已由其他用户分享，非管理员分享请求返回 409，不静默覆盖
   （`SharedService.js:153-163`；`index.js:443-445`）。
4. 撤回/共享区删除：仅分享者本人或管理员可操作；无索引记录时一律 403，不论请求者
   是谁（`SharedService.js:216-230`）。
5. `/delete?fromShared=true` 复用同一套撤回逻辑，不另开权限分支
   （`index.js:373-383`）。
6. 权限身份取自服务端 `req.user`；管理员判定兼容 `req.user.admin`、
   `req.user.profile.admin`，单用户模式（无 `req.user`）视为管理员
   （`UserHelper.js:113-127`）。
7. 共享区元数据写操作在 per-sharedDir 异步锁内完成，并强制绕过 30s 缓存读取远端最新
   索引（`SharedService.js:42-54`、`:153-156`、`:211-213`）。

## 备选方案

- **任意登录用户可撤回（修复前行为）**：即 M3 缺陷，等于共享区文件可被任意用户删除；
  已否决。
- **只允许分享者本人撤回、管理员也无例外**：共享区跨账号，分享者离职/改名后孤儿分享
  无人可清理；且 AGENTS.md §2.1 明确保留管理员例外；已否决。
- **用 WebDAV 服务端 ACL 表达权限**：群晖、Alist、Nextcloud 等对 ACL 支持差异大，无法
  保证可移植；应用层索引才是统一信任锚；已否决。
- **按文件名里的 handle 前缀判归属**：共享区 COPY 保留原文件名，且文件可被外部直接
  PUT 进共享区，文件名可伪造，不能作为权限依据；已否决。
- **无索引也允许撤回（幂等删除）**：会让任意用户删掉外部 PUT 的文件；已否决。

## 后果

- 正面：越权撤回被阻断，回归测试覆盖无索引 403 与「Bob 不能撤回 Alice 的分享」
  （`tests/security.test.js:285-305`、`tests/share.test.js:304-314`）；409 阻止同名静默
  覆盖；管理员可清理孤儿分享；共享区与用户轮转解耦（`SharedService.js:13`）。
- 负面：索引是唯一事实来源，外部直接 PUT 进共享区的文件无法通过插件撤回（403），只能
  手工处理；管理员绕过权限时没有审计日志。
- 负面：管理员与他人分享同名文件时会覆盖文件并改写元数据归属
  （`SharedService.js:159-163`、`:172-183`），原分享者随后撤回会得到 403；该行为是否
  符合预期待确认。
- 需要配套做的事：
  - 保留并扩充 `tests/share.test.js` / `tests/security.test.js` 中权限与 409 用例；
  - 共享区元数据规模增大后的读写开销属于已知残余风险（`CODE_REVIEW.md:135`），多实例
    部署建议关闭共享模式；
  - 任何放宽「仅分享者本人或管理员」的改动，都必须先以新 ADR 修订本决策。
