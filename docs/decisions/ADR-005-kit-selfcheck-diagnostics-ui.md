# ADR-005：在「服务设置」页展示 UI Kit 运行时诊断

- 状态：已接受
- 日期：2026-10-27
- 相关：ui-kit v2.8.0 的 `NVUI.selfCheck()`；v1.3.0 已接入 console 告警

## 背景

v1.3.0 起，插件在加载 UI Kit 后调用 `NVUI.selfCheck({ expect })`，把版本/令牌/玻璃状态异常
收敛为一条 `[ST-WebDAV]` console 告警（`src/client/index.js`）。但这带来两个问题：

1. **普通用户看不到**：面板样式错乱时，用户不会打开控制台；issue 报告缺少
   「加载来源 / kit 版本 / CSS 版本 / 玻璃状态 / 自检问题」这些关键环境信息，
   排查成本高（见 `docs/ui-kit/issue-reporting.md` 要求的 7 项要素）。
2. **多扩展共存是常态**：宿主里可能同时加载多个扩展各自内嵌不同版本的 kit，
   CSS 与 JS 版本不一致时只表现为样式静默失效，没有可见信号。

## 决策

在面板「服务设置」标签页新增**只读**的「运行时诊断」折叠区，展示：

- UI Kit 加载来源（宿主达标复用 / 内置本地副本 / 宿主旧版降级 / CDN 兜底）；
- UI Kit 版本、CSS 是否加载及 CSS 版本；
- 玻璃状态（supported / unsupported / unknown，是否已自动回退）；
- 最近一次自检结论（通过，或 issues 列表）。

配套约束：

1. 只读展示，不新增配置项、不写任何持久化状态；
2. 提供「重新检测」按钮，重新调用 `NVUI.selfCheck()` 并刷新展示；
3. 不新增依赖，不修改 `src/client/vendor/ui-kit/`；
4. 自检失败或 kit 不支持时静默降级（展示「未提供自检能力」），不阻断面板。

## 备选方案

- **仅保留 console 告警**：不增加 UI 复杂度，但用户不可见、issue 信息仍缺失；已否决。
- **独立调试页/设置弹窗**：信息量接近，但入口更深、实现更重；已否决。
- **自动上报到远端**：涉及隐私与网络副作用，且与「数据只在自己 WebDAV」的产品定位冲突；
  已否决。
- **不做展示**：等于把 v1.3.0 的自检结果锁在控制台里，收益无法触达用户；已否决。

## 后果

- 正面：用户可自助确认「样式问题是不是 kit 版本/加载来源导致」；issue 报告可直接附诊断行；
  多扩展共存场景有可见信号。
- 负面：设置页多一个折叠区，需随 kit 自检字段演进维护（字段读取做了缺省兜底）；
  诊断信息展示的是运行时值，不是权威配置（权威仍是 `/config`）。
- 需要配套做的事：
  - `src/client/index.js` 的 `formatKitDiagnostics()` 保持**纯函数**，便于审阅与后续测试；
  - 诊断信息不得包含凭据/Cookie/用户数据（当前仅版本与状态位）；
  - 若未来需要「导出诊断」，另写 ADR，不要在展示层直接拼接敏感信息。
